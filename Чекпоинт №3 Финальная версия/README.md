========================================================================
    «Отклик» — платформа доверительных анонимных обращений
========================================================================

Проект разработан в рамках хакатона «Кубок Федерации» по кейсу 
предотвращения травли, буллинга, эмоционального и физического давления 
в образовательных организациях.

Платформа решает проблему сокрытия и формального «гашения» конфликтов на 
уровне школы, вытаскивая проблемы на уровень городских психологических и 
правовых служб в обход школьной администрации.

🚀 1. ИНСТРУКЦИЯ ПО ЛОКАЛЬНОМУ ЗАПУСКУ
========================================================================

Сервис поддерживает два варианта локального запуска из чистого клона:

ВАРИАНТ А. Запуск через Docker (Рекомендуемый)
------------------------------------------------------------------------
Развёртывание одной командой через Docker Compose:

    docker compose up --build

После завершения сборки веб-интерфейс доступен по адресу:
http://localhost:5000


ВАРИАНТ Б. Локальный запуск без деплоя (Python)
------------------------------------------------------------------------
Для тестирования без контейнеризации (требуется Python 3.9+):

1. Установите зависимости:
   pip install Flask Flask-SQLAlchemy Flask-Login Pillow

2. Запустите приложение:
   python app.py

3. Откройте в браузере: http://127.0.0.1:5000
   (База данных SQLite и тестовые аккаунты создаются автоматически).

🛡️ 3. МОДЕЛЬ ПРИВАТНОСТИ И БЕЗОПАСНОСТИ (Раздел 6 ТЗ)
========================================================================

1. Принцип нулевого доверия к персональным данным:
   - Сервис не запрашивает и не сохраняет имя, телефон, email, адрес или 
     номер школы/класса заявителя.
   - IP-адреса и User-Agent НЕ связываются с обращениями и НЕ пишутся в БД.
   - Сторонние аналитические трекеры полностью отсутствуют.

2. Очистка метаданных изображений (EXIF / GPS):
   - Все прикрепляемые скриншоты (до 5 файлов) обрабатываются библиотекой 
     Pillow: из них безвозвратно вырезаются EXIF и GPS-координаты.

3. Строгое разграничение доступа (Матрица прав):
   - Оператор видит только исходный текст для первичной сортировки. 
     Доступа к переписке эксперта с заявителем у него нет.
   - Эксперт не знает личности заявителя ни на одном из этапов.
   - Администратор не имеет доступа к текстам обращений и переписке. 
     В выгрузки попадают исключительно метаданные.

4. Безопасность переменных окружения (.env):
   - Файлы конфигурации .env.example содержат безопасные значения для 
     автоматической сборки. На продуктовом сервере секретные ключи 
     переопределены в изолированном окружении.


========================================================================
🔑 4. ТРЕК-НОМЕРА И УВЕДОМЛЕНИЯ (Разделы 4.7 и 4.8)
========================================================================

- Формат трек-номера: ОТК-XXXX-XXXX (8 значащих символов).
- Алфавит без коллизий: 23456789ABCDEFGHJKMNPQRSTUVWXYZ (без 0/O, 1/I/l).
- Криптостойкость: Генерация через системный модуль secrets.
- Защита от перебора: Rate limiting — не более 5 попыток ввода в минуту.
- Уведомления: Заявитель сохраняет закладку с трек-номером. Есть кнопки 
  «Скопировать» и «Сохранить». Поддерживается добровольное поле 
  экстренного контакта для оператора при кризисных ситуациях.


========================================================================
🆘 5. КРИЗИСНЫЙ СЦЕНАРИЙ И РЕШЕНИЕ ОТКРЫТОЙ ЗАДАЧИ (Раздел 5.3)
========================================================================

- Мгновенная детекция: Автоматический анализ текста по словарю триггеров 
  (насилие, суицид, оружие, угроза жизни).
- Немедленная помощь: Заявителю выводится плашка с прямыми телефонами 
  экстренных служб (112 и 8-800-2000-122) без блокировки ввода.
- Приоритет вне очереди: В кабинете оператора кризисные обращения 
  поднимаются в самый верх с пометкой «⚠️ Срочно / Кризис».
- Решение открытой задачи 5.3 (Межведомственное содействие):
  При возникновении непосредственной угрозы жизни ребёнка оператор 
  инициирует режим межведомственного взаимодействия. Заявителю в чат 
  направляется запрос с объяснением необходимости привлечения городских 
  служб защиты детей. Контакт передается только по явному согласию.


========================================================================
🎨 6. ПОЗИЦИОНИРОВАНИЕ И ИНТЕРФЕЙС (Раздел 3.1)
========================================================================

- Tone of Voice: При выборе «Школьник» интерфейс бережно общается на «ты» 
  («Расскажи о том, что происходит своими словами»). При выборе «Родитель» 
  или «Педагог» — переходит на официальное «вы».
- Бережный UX: Без агрессивных предупреждений, капслоков и красных рамок.
- Mobile-First: Полностью адаптирован под мобильные экраны смартфонов.

📋 7. СПИСОК НЕРЕАЛИЗОВАННОГО (BACKLOG)
========================================================================

1. Web Push / PWA Service Workers: Доставка пуш-уведомлений на смартфон 
   без привязки к почте или номеру телефона.
2. ML-Классификатор: Интеграция NLP-модели для автоматического 
   определения категории обращения на этапе ввода текста.
3. Cron-планировщик: Перевод неактивных тикетов в статус «Закрыто без ответа» 
   при отсутствии активности заявителя в течение 14 дней.
